# イツカエル？ 〜震災帰宅大作戦〜　試作版 v0.1

**急がば待て！ 帰すタイミングは、あなた次第。**

大地震で電車が止まった日、都心の駅周辺にいる人を、さいたま市・川口・草加方面へ「いつ・どうやって」帰すかを考える、データを元にした防災ゲームの試作版です。

▶ 遊ぶ：https://game.mikami-takashi.net/

> 条件を簡略化したゲームで、現実の被害を予測するものではありません。全員帰宅の時刻などは、このゲームの簡略モデルでの値です。

## 1. 遊び方

1. 都内の駅（新宿・池袋・永田町・上野・東京）に触れて、指を上へすべらせて選ぶ
   - 🚃 電車で帰す（家まで電車が通じている人だけ）
   - 🔵🟠🔴 歩いて帰す（電車で帰れない人のうち、家までの距離が10km未満／10〜20km／20km超の色ごと）
   - ✋ 全部待つ
2. 駅の箱の上のゲージ（駅へ向かう・乗車を待つ人）が上がりすぎると、その駅は20分間の入場規制になります
3. 帰すタイミングによって、道や駅の混雑、救急車の通りやすさ、途中で歩けなくなる人の数が変わります

はじめての人は「練習1」から。

## 2. レビューのお願い（v0.1）

このレビューで確かめたいのは「AIで作ったものが、ゲームとして成立しているか」です。防災の前提が現実に合っているかの検証は、このレビューの対象外です。

| 観点 | 聞きたいこと | Issueのひな形 |
|---|---|---|
| 操作 | 最初にどこで迷ったか | 操作 |
| ゲーム性 | もう一度遊びたいか。何を変えて試したくなるか | ゲーム性 |
| 実装 | 結果を不自然に左右する処理や、不具合がないか | 実装・不具合 |

特に見てほしい実装：`src/engine.js` の乗車処理（全駅の乗車待ちを駅に着いた順に並べて輸送枠を割り当てる部分）、途中駅での乗車、背景の利用者、輸送枠の繰り越し、`src/policies.js` の評価の重みづけ。

## 3. 構成とテスト

```
index.html        公開するゲーム（これ1枚で動く）
build.js          src/ から index.html を組み立てる： node build.js
src/engine.js     計算（人の移動、電車、駅の混雑、救急車）
src/policies.js   評価、好成績の帰し方の探索、練習ステージ
src/ui.js         画面と操作
src/shell.html    HTML・CSS
src/data.json     ゲームが使うデータ（加工後の値）
test/load.js      index.html から計算部分をそのまま取り出して読み込む
test/test.js      検証テスト： node test/test.js
```

テストは、公開する `index.html` の計算部分（目印のコメントで囲んだ部分）をそのまま取り出して実行します。ゲームとテストは同じ計算コードです。Node.js 18以降があれば、追加のインストールなしで動きます。

## 5. モデル独自の仮定

- 1つの点は500人。駅の箱は、その周辺の区で働く・学ぶ対象者のうち地域内で待っている人で、駅全体の人数ではない
- 23区の職場を5つの駅周辺と県境近くの区に割り振る（文京区は池袋31%・上野69%、駅の乗降人員から推計）
- ゲージの満杯の基準は、その駅に発着する埼玉方面の路線の輸送力40分ぶん（ゲーム上の混雑目安で、ホームの収容人数ではない）
- 電車は、複数の駅で路線の輸送枠を分け合う簡略モデル。輸送力は朝ピークの上り方向の値を帰宅方向の目安とし、再開直後は50%
- 枠の端数は500人分まで次の分に繰り越す。空席の枠はためない
- 県境近くの区で働き、家まで10kmを超える約3.3万人は、赤羽・北千住を代表地点として電車の枠を使う（全員電車・120分のうちに駅に着く、という一つの条件）
- 歩く速さは時速4km。疲れて歩けなくなる距離は人ごとに10〜20kmの間（都の考え方に合わせた設定）
- 一時滞在施設は発災から約6時間後に開く。都立施設を含まない区の数字には、都立施設の数×約350人を上乗せ（暫定）
- 救急車は30分おきに、決めた道を走る
- 会社などの「帰す・待たせる」の判断に全員が従う
- 余震・火災・落下物などによる道の安全、救助活動への影響は扱わない

## 7. 検証済みの事項（このモデルの中で）

`node test/test.js` で確かめられます（3通りの帰し方：ゲージ5割で少しずつ帰す／全員すぐ帰す／発災翌日8:50に全駅を帰す）。

- 人数が毎分ずれない（消えない・増えない）。全員が帰宅する。背景の利用者3.3万人も全員乗車する
- 輸送枠を前借りしない（毎分、使用累計 ≦ 供給累計）。繰り越しは500人分（または1分の枠）まで
- 移行前（Claude上の公開版の組み立て方法）と移行後（build.js）で、組み立てた結果が、計算部分の目印のコメントを除いて一致する。3通りの帰し方の結果も一致する

| 帰し方 | 全員帰宅 | へとへと | あきらめて歩いた | 途中駅で乗車 |
|---|---|---|---|---|
| ゲージ5割で少しずつ帰す | 発災翌日18:27 | 0人 | 0人 | 0人 |
| 全員すぐ帰す | 発災翌日18:35 | 284,500人 | 0人 | 18,500人 |
| 発災翌日8:50に全駅を帰す | 発災2日後7:10 | 180,000人 | 153,500人 | 114,000人 |

## 8. 未検証の事項・既知の課題

- **駅の処理順による偏りが一部残っている（既知の課題）**：同じ時刻に駅に着いた人の乗る順番と、歩く人の処理順が、作られた順（駅の並び順）で決まる。「ゲージ5割で少しずつ帰す」では、駅の並びを逆にすると全員帰宅の平均が約13分変わる（乱数8通り、標準誤差約4分）。テストに参考値として表示している。乱数で順番を決める修正案は、計算の変更になるためv0.2で扱う
- 現実の駅や路線の混雑を再現できているか（2011年の駅ごとの混雑の記録などは、今回は取得・確認できていない）
- 14時台に都内にいる割合が区によって違う理由（大学が多い、など）は仮説
- 元データ（国勢調査・PT調査）から `data.json` を作る加工手順は、このリポジトリに含めていない
- 動作確認は、パソコンのブラウザ（Chromium）とiPhoneの一部のみ
